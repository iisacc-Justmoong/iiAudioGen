# iiAudioGen 기초 구조

`iiAudioGen` 0.2.0은 사운드 생성 AI를 연결하기 위한 C++23 SDK의 초기 골격이다. Qt와 외부 런타임 의존성 없이 표준 라이브러리만 사용한다. 현재 구현에는 실제 AI 모델 로더와 추론 백엔드가 없다.

## 공개 계약

`GenerationRequest`는 프롬프트, 생성 길이(초), 샘플 레이트(Hz), 채널 수, 선택적 시드를 전달한다. 기본값은 5초, 44,100Hz, 모노이며 시드는 미지정이다. 백엔드마다 지원하는 생성 길이와 오디오 형식이 다르므로 구체적인 지원 범위는 백엔드가 판단한다.

`GenerationResult`는 채널을 번갈아 배치한 부동소수점 PCM 샘플과 실제 샘플 레이트·채널 수를 담는다. 스테레오 샘플의 순서는 첫 프레임의 왼쪽·오른쪽, 다음 프레임의 왼쪽·오른쪽이다. 샘플의 유효성, 프레임 정렬, 요청과 출력 형식의 일치 여부는 백엔드의 책임이다. 현재 골격은 결과를 변환하거나 재검증하지 않는다.

`GenerationOutcome`은 `std::expected<GenerationResult, Error>`이다. `ModelLoadOutcome`은 `std::expected<void, Error>`이며 모델 로딩 성공에는 별도의 결과 데이터가 없다. 오류는 잘못된 요청을 나타내는 `InvalidRequest`, 백엔드 또는 모델 로더 부재를 나타내는 `BackendUnavailable`, 생성 실패를 나타내는 `GenerationFailed`, 잘못된 모델 입력을 나타내는 `InvalidModel`, 모델 로딩 실패를 나타내는 `ModelLoadFailed`로 구분한다.

## 모델 입력 슬롯

`Generator::loadModel(const std::filesystem::path& modelPath)`는 로컬 모델 파일 또는 모델 디렉터리의 경로를 받는 공개 진입점이다. C++ 표준 경로 타입을 사용하며, 호출 시 실제 모델 로딩은 보유 중인 백엔드의 `loadModel()`에 위임한다.

생성기는 빈 경로와 널 문자를 포함한 경로를 `InvalidModel`로 거절한다. 백엔드가 없으면 `BackendUnavailable`을 반환한다. 나머지 경로는 정규화, 문자열 변환, 파일 접근 없이 한 번 그대로 전달하며, 성공 또는 오류를 호출자에게 그대로 반환한다. 경로가 존재한다는 사실이나 특정 확장자만으로 모델 로딩 성공을 판정하지 않는다.

파일 존재와 접근 권한, 모델 구조와 가중치 검증, 모델 상태, 교체 시 이전 모델의 처리 정책은 백엔드가 담당한다. 백엔드는 로딩이 실제로 완료된 경우에만 성공을 반환해야 한다. `Backend::loadModel()`의 기본 구현은 `BackendUnavailable`이므로 모델 로더를 아직 구현하지 않은 백엔드가 성공을 보고하지 않는다. 기존 생성 전용 백엔드는 로딩 메서드 재정의 없이 다시 빌드할 수 있다.

모델 로딩과 생성은 `loadModel(modelPath)` → `generate(request)`의 순서로 같은 백엔드를 사용한다. 로딩 전 생성 호출의 허용 여부는 백엔드가 결정한다. 코어는 별도의 모델 저장소, 모델 포맷별 분기, 자동 다운로드, 비동기 작업 시스템을 추가하지 않는다.

이 설계는 모델을 로딩한 파이프라인에 별도로 생성 요청을 전달하는 [AudioLDM2 공식 사용 예제](https://huggingface.co/docs/diffusers/api/pipelines/audioldm2)를 참고한 것이다. 경로 타입 선택에는 C++의 파일 경로 전달 타입을 설명하는 [WG21 P1030R0](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2018/p1030r0.pdf)을 참고했다. 해당 런타임이나 논문의 제안 타입을 의존성으로 도입한 것은 아니다.

## 책임과 교체 경계

`Backend`는 모델 로딩과 생성 요청을 받아 성공·결과 또는 오류를 반환하는 인터페이스이다. 모델 탐색, 로딩, 추론과 자원 관리는 실제 백엔드 구현에서 담당한다. 특정 모델 포맷이나 실행 장치에 대한 가정은 추가하지 않았다.

`Generator`는 전달받은 `std::shared_ptr<Backend>`를 보유한다. 호출자가 자신의 참조를 해제하여도 생성기가 보유한 백엔드는 유지된다. 호출은 동기식이며, 동시 호출의 안전성은 백엔드 구현이 결정한다. 예외를 오류 값으로 변환하는 기능은 없으므로 백엔드는 예상 가능한 실행 실패를 `Error`로 반환해야 한다.

생성기는 먼저 프롬프트가 비어 있거나 ASCII 공백으로만 구성되었는지, 생성 길이가 유한한 양수인지, 샘플 레이트와 채널 수가 0이 아닌지 확인한다. 잘못된 요청은 백엔드를 호출하지 않는다. 유효한 요청에 백엔드가 없으면 `BackendUnavailable`을 반환한다. 백엔드가 있으면 요청을 한 번 전달하고 결과 또는 오류를 그대로 반환한다.

## 빌드와 검증

CMake 패키지는 `find_package(iiAudioGen 0.2 CONFIG REQUIRED)`와 `iiAudioGen::iiAudioGen` 타깃을 제공한다. 공개 헤더는 `<iiAudioGen/iiAudioGen.h>`이다. C++23 요구사항은 소비자에게 전파된다. 공유·정적 라이브러리 구성을 지원하며 모든 빌드 출력은 모듈의 `build/` 아래에 둔다. 백엔드 가상 인터페이스 추가로 공유 라이브러리 ABI 버전은 `0.2`이며, 기존 소비자와 백엔드는 새 헤더로 다시 빌드해야 한다.

행동 테스트는 요청 검증, 백엔드 미설정 오류, 요청·결과 전달과 수명 유지, 오류 전파를 검증한다. 모델 입력 테스트는 빈 경로·널 문자 거절, 파일·디렉터리 경로 전달, 로딩과 생성의 동일 백엔드 사용, 로더 부재와 로딩 오류 전파를 확인한다. 테스트용 로더는 경로 전달만 검증하며 실제 가중치를 읽지 않는다. 테스트 백엔드의 고정 PCM 값은 인터페이스 검증용 데이터이며 실제 AI 생성 결과가 아니다. 설치 소비자 테스트는 소스 디렉터리 참조 없이 설치된 헤더·라이브러리·CMake 패키지의 모델 입력 슬롯과 생성 API를 사용하는지 확인한다.

실제 모델 다운로드, 학습, 추론, 재생, WAV 등 파일 인코딩, 가속 장치, GUI 연결은 이번 골격에 포함되지 않는다. 운영 설치본의 변경과 플랫폼별 실행 검증은 별도의 후속 작업이다.
